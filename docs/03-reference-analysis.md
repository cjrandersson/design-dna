# 03 — Reference analysis

A reference is not an instruction to imitate.

It is evidence about a design preference.

The job is to extract **why** the reference works, then translate that logic into the current project.

## Reference decomposition

For every reference, analyse these layers separately.

### 1. Composition

- symmetry vs asymmetry
- centred vs offset
- dense vs sparse
- edge-to-edge vs framed
- foreground / background depth
- balance of empty and occupied space

### 2. Scale

- what is oversized?
- what is intentionally tiny?
- how aggressive is the contrast between levels?
- does anything break the frame?

### 3. Geometry

- sharp / soft
- rigid / organic
- modular / continuous
- repeated / irregular
- what shape language ties the design together?

### 4. Typography

- neutral / expressive
- editorial / utilitarian
- compressed / airy
- aligned / intentionally skewed
- text as information vs text as graphic form

### 5. Colour

- number of colours
- contrast structure
- warm / cool balance
- material colour vs interface colour
- semantic vs decorative use

### 6. Material / texture

- matte
- glossy
- translucent
- grainy
- printed
- degraded
- metallic
- ceramic
- paper-like
- digital-flat

### 7. Rhythm

- repeated spacing
- interruptions
- grouping
- pacing
- visual rests
- density changes

### 8. Interaction, if applicable

- what feels clickable / playable?
- what reveals state?
- what remains hidden until needed?
- what moves?
- what is direct manipulation?

### 9. Emotional quality

Ask for plain language.

Examples:

- quiet
- awkward in a good way
- elegant
- industrial
- handmade
- strange
- serious
- warm
- clinical
- playful
- ceremonial
- raw
- precise

Emotional language often captures the useful part of a reference faster than style labels.

# The borrow / reject protocol

For every important reference, write:

```text
REFERENCE:
[image / product / project]

BORROW:
- ...
- ...
- ...

DO NOT BORROW:
- ...
- ...

UNDERLYING PRINCIPLE:
[one sentence]
```

Example:

```text
REFERENCE:
Fors Opal

BORROW:
- restrained hierarchy
- instrument-like directness
- large playable controls
- contextual complexity

DO NOT BORROW:
- exact colours
- exact component layout
- branded visual motifs

UNDERLYING PRINCIPLE:
A complex instrument can feel calm when only the currently meaningful controls compete for attention.
```

---

# Multiple references

When several references are supplied, do not average them into generic mush.

Instead identify the role of each reference.

Example:

```text
Reference A = hierarchy
Reference B = typography
Reference C = texture
Reference D = interaction
```

Then combine principles deliberately.

Avoid:

> “Make it 25% A + 25% B + 25% C + 25% D.”

That usually destroys what made each reference useful.

---

# What to ask when a reference feels important but unclear

Instead of asking:

> What do you like about it?

use narrower questions:

- Is it the proportion or the actual shapes?
- Is the attraction mostly typography or composition?
- Do you like the material feeling or the colour palette?
- Is the useful part visual or behavioural?
- Should this influence the whole system or only one element?

The purpose is to locate the signal without making the user translate everything into professional design vocabulary.
